# Установка КИОСК ДОНЕР на хостинг Beget

Пошаговая инструкция для домена **piz.itop7.ru**. Всё, что помечено «проверьте», зависит от
текущих настроек вашей панели — интерфейс Beget иногда меняется.

## 0. Что уже готово и что понадобится

| Параметр | Значение |
|---|---|
| Домен | `piz.itop7.ru` (сейчас отвечает по HTTP, PHP 8.2) |
| Аккаунт Beget | логин `mahmadgv` (первые символы имени базы) |
| Сервер / FTP | `mahmadgv.beget.tech`, порт FTP 21 |
| Папка сайта | `~/piz.itop7.ru/public_html` |
| База данных | `mahmadgv_piz` |
| Пользователь БД | `mahmadgv_piz` |
| Пароль БД | в файле `info.txt` (не публикуйте его) |
| Хост БД | `localhost` |
| PHP | 8.2 (подойдёт 8.1–8.3) |

Понадобятся: доступ в панель https://cp.beget.com и пароль от аккаунта. Если панель временно
недоступна — проверьте новости на сайте Beget, у провайдера бывают восстановительные работы.

> **Важно:** не загружайте на хостинг `info.txt`, `.git`, `.tools` и `товар.xlsx`.
> Пароль базы вводится только в браузере на шаге установки.

## 1. Включите SSH и узнайте сервер

1. Войдите в https://cp.beget.com.
2. На главной странице включите **SSH** (по умолчанию он выключен).
3. В блоке «Техническая информация» скопируйте **имя сервера** — обычно `mahmadgv.beget.tech`.

Проверка с компьютера (macOS/Linux/Windows 10+):

```bash
ssh mahmadgv@mahmadgv.beget.tech
```

Пароль — тот же, что от панели Beget. При первом подключении введите `yes`.

## 2. Проверьте PHP в панели

1. **Сайты** → `piz.itop7.ru` → **PHP**.
2. Выберите **PHP 8.2** (или 8.1/8.3).
3. Убедитесь, что включены расширения: `pdo_mysql`, `mbstring`, `gd`, `zip`, `fileinfo`.
   Обычно они включены по умолчанию.
4. Лимиты: `upload_max_filesize ≥ 8M`, `post_max_size ≥ 10M`, `memory_limit ≥ 128M`.

Если чего-то не хватает, установщик покажет это на первом экране и подскажет, что включить.

## 3. Загрузите проект

### Вариант А — через Git (рекомендуется, обновления одной командой)

Репозиторий публичный, поэтому клонируется без ключей:

```bash
ssh mahmadgv@mahmadgv.beget.tech
cd ~/piz.itop7.ru

# сохраните текущую заглушку, если она есть
mv public_html public_html.backup-$(date +%F) 2>/dev/null || true

git clone https://github.com/mahmadali91/piz.git public_html
cd public_html
```

Если репозиторий станет приватным, сначала настройте деплой-ключ — см. [GITHUB.md](GITHUB.md).

### Вариант Б — через FTP / файловый менеджер

1. Подключитесь FileZilla:

   | Поле | Значение |
   |---|---|
   | Хост | `mahmadgv.beget.tech` |
   | Протокол | FTP |
   | Порт | 21 |
   | Логин | `mahmadgv` |
   | Пароль | пароль от панели Beget |

2. Перейдите в `piz.itop7.ru/public_html` (или `public_html` в корне аккаунта).
3. Загрузите **содержимое проекта**: `index.php`, `.htaccess`, папки `src`, `assets`, `config`,
   `data`, `database`, `docs`, `uploads`, `storage`, `tools`, `README.md`.
4. **Не загружайте:** `config/config.php` (создастся сам), `info.txt`, `.git`, `.tools`, `товар.xlsx`.

> В FileZilla включите показ скрытых файлов, иначе `.htaccess` не загрузится, и сайт будет отдавать 404.

### Вариант В — ZIP-архив (самый простой)

1. Возьмите локальный архив `dist/piz-kiosk-v1.24.26-6.zip` (в Git он не хранится) или скачайте исходники на GitHub:
   **Code → Download ZIP**.
2. Панель Beget → **Файловый менеджер** → папка `piz.itop7.ru/public_html`.
3. Загрузите архив в эту папку и распакуйте.
4. Убедитесь, что в корне `public_html` лежат `index.php` и `.htaccess` (включите показ скрытых файлов).
5. Удалите архив с сервера.

### Права доступа

```bash
cd ~/piz.itop7.ru/public_html
mkdir -p uploads/products storage/logs

# файлы и каталоги — стандартные права, без лишнего executable-бита
find . -path ./.git -prune -o -type f -exec chmod 644 {} \;
find . -path ./.git -prune -o -type d -exec chmod 755 {} \;

# только эти каталоги должны быть доступны на запись
find uploads storage config -type d -exec chmod 775 {} \;
find uploads storage config -type f -exec chmod 664 {} \;
chmod 640 config/config.php 2>/dev/null || true
```

> Не используйте `chmod -R 775` на всём проекте: Git начнёт видеть изменения прав у файлов,
> и `git pull` будет ругаться. Права `755/644` достаточно, запись нужна только `uploads`, `storage`, `config`.

Если после установки `config/config.php` создался с правами `640` — это нормально.

## 4. Установите приложение

1. Откройте **http://piz.itop7.ru/setup**.
2. Проверьте блок «Требования сервера» — всё должно быть зелёным.
3. Введите доступы к базе:

   | Поле | Значение |
   |---|---|
   | Хост | `localhost` |
   | Порт | `3306` |
   | Имя базы | `mahmadgv_piz` |
   | Пользователь | `mahmadgv_piz` |
   | Пароль | из `info.txt` |

4. Нажмите «Проверить и продолжить». Установщик создаст таблицы и загрузит 35 товаров из Excel.
5. Создайте администратора: имя, логин (например, `admin`), пароль от 8 символов и название киоска.
6. После входа откройте **Товары** и оформите приход — начальные остатки в файле Excel не указаны,
   поэтому они равны нулю.

## 5. Включите HTTPS

Сейчас `https://piz.itop7.ru` не отвечает, а `http://` работает. Это лечится сертификатом:

1. Панель Beget → **Сайты** → `piz.itop7.ru` → **SSL-сертификаты**.
2. Выберите бесплатный **Let's Encrypt**, укажите e-mail, дождитесь выпуска (обычно 5–15 минут).
3. Включите перенаправление HTTP → HTTPS, если такой переключатель доступен.
4. Проверьте: https://piz.itop7.ru — должен открыться вход.
5. Зайдите в приложение и убедитесь, что вход работает по HTTPS.

После включения HTTPS cookie сессии автоматически становятся `Secure`, HSTS включается сам.

## 6. Проверьте работу

- https://piz.itop7.ru/healthz → `{"ok":true,...}`.
- Войдите администратором.
- **Настройки → Система**: PHP, MySQL, все таблицы, запись в `uploads` и `config` — зелёные.
- Создайте тестовый товар с фото.
- Оформите тестовую продажу на 1 ₽, проверьте чек и отмену.
- Заведите кассира и проверьте, что он видит только кассу и свои продажи.

## 7. Обновления

### Git

```bash
ssh mahmadgv@mahmadgv.beget.tech
cd ~/piz.itop7.ru/public_html
git pull --ff-only
```

`config/config.php`, `uploads/` и `storage/` не входят в Git и не перезаписываются.
Если менялась схема БД, выполните миграцию:

```bash
php8.2 tools/migrate.php
```

Она добавляет таблицы приходов, списаний, смен и настройку отрицательных остатков.

Схема создаётся установщиком один раз.

### FTP

Загрузите изменённые файлы поверх, **кроме** `config/config.php` и содержимого `uploads/`.

## 8. Резервные копии

1. **Панель Beget** делает ежедневные бэкапы аккаунта — уточните глубину хранения в тарифах.
2. Раз в неделю скачивайте:
   - дамп базы через **phpMyAdmin → Экспорт**;
   - папку `uploads/` (фото товаров) через FTP/файловый менеджер;
   - CSV из разделов «Продажи» и «Товары».
3. Перед крупными обновлениями делайте бэкап вручную.

## 9. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| 500 Internal Server Error | Смотрите `storage/logs/php-error.log`. Чаще всего — нет прав на `config/`, `uploads/` или `storage/`. |
| «Не удалось подключиться к базе» | Проверьте `localhost`, имя базы/пользователя и пароль. Пользователь и база должны совпадать с префиксом `mahmadgv_`. |
| Все страницы 404, кроме главной | Не загрузился `.htaccess` или выключен `mod_rewrite`. Включите показ скрытых файлов и перезалейте `.htaccess`. |
| 403 на всём сайте | Проверьте, что корень сайта указывает на папку с `index.php`, а не на родительскую. |
| Фото не загружаются | Нет прав на `uploads/` или не включён GD. Выдайте `775` и включите `gd`. |
| Excel не импортируется | Не включён `zip` — сохраните файл как CSV (кнопка «Скачать шаблон»). |
| Не приходит письмо/нет HTTPS | SSL выпускается в панели; проверьте DNS домена. |
| Сайт открывается, но пустой | Откройте `/setup` — возможно, установка не завершена. |

## 10. Чек-лист запуска

- [ ] SSH включён, проект загружен в `public_html`.
- [ ] `.htaccess` на месте, права `775` на `uploads`, `storage`, `config`.
- [ ] PHP 8.2, расширения `pdo_mysql`, `mbstring`, `gd`, `zip`.
- [ ] `/setup` пройден, база подключена, каталог загружен.
- [ ] Администратор создан, пароль сохранён в менеджере паролей.
- [ ] HTTPS включён, HTTP перенаправляется на HTTPS.
- [ ] Тестовая продажа и отмена работают, чек печатается.
- [ ] Приход товара и фото работают.
- [ ] Кассир создан и ограничен в правах.
- [ ] Резервная копия базы и `uploads/` снята.


## 11. После обновления версии «КИОСК ДОНЕР»

1. Сделайте бэкап базы.
2. `git pull --ff-only`.
3. `php8.2 tools/migrate.php`.
4. Проверьте: **Товары и остаток**, **Приход**, **Расход**, **Смена**, настройку отрицательных остатков.
5. При необходимости перегенерируйте фото и иконки:
   ```bash
   php8.2 tools/maintenance.php photos:generate --all
   ```
6. Очистите кеш PWA: в `sw.js` уже поднята версия; пользователям достаточно обновить страницу.
