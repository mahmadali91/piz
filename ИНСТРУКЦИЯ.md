## 3. Первый вход и остатки

1. Откройте http://piz.itop7.ru (после SSL — https://piz.itop7.ru).
2. Войдите под администратором.
3. Откройте **Товары**. В каталоге 35 позиций, остаток 0.
4. Нажмите **Приход**, выберите товар, укажите количество и закупочную цену, сохраните.
5. Повторите для товаров, которые есть в наличии.
6. Проверьте дашборд: появятся стоимость остатка и блок «Пора докупить».

## 4. Ежедневная работа

### Касса

1. **Касса** → найдите товар по названию/артикулу.
2. Нажмите карточку, чтобы добавить в чек; количество меняется кнопками `+`/`−`.
3. При необходимости укажите скидку в рублях.
4. Выберите оплату: **Наличные**, **Карта** или **Перевод**.
5. Для наличных введите полученную сумму — сдача посчитается сама.
6. Нажмите **Оформить**.
7. В открывшемся чеке: **Печать** (80 мм), **Открыть чек**, **Новая продажа**.

Нельзя продать больше остатка и получить меньше суммы к оплате. Повторное нажатие «Оформить» не создаёт дубль.

### Товары

- **Добавить товар** — название, фото (JPG/PNG/WEBP до 6 МБ), категория, закупка, цена, единица, минимальный остаток, начальный остаток.
- **Приход** — увеличивает остаток; можно обновить закупочную цену.
- **Инвентаризация** — ставит точный фактический остаток.
- **В архив** — убирает из кассы, сохраняя историю; вернуть можно при фильтре «Архив».
- **Экспорт** — CSV текущего списка.
- **Импорт** — `.xlsx` или `.csv`, см. раздел 5.

### Продажи

- История чеков с фильтрами по периоду, оплате, статусу и номеру.
- Открытие чека: состав, прибыль, печать.
- **Отменить продажу** — товары возвращаются на склад, сумма исключается из выручки; чек остаётся в истории.
- Кассир видит только свои продажи; администратор и управляющий — все.

### Отчёты

Периоды: сегодня, 7 дней, 30 дней, этот месяц, всё время, свои даты.
Показатели: выручка, прибыль, маржинальность, средний чек, скидки, отмены, сравнение с предыдущим периодом, график, оплата по способам, топ товаров, склад.
Экспорт: **Дни**, **Товары**, **Склад** (CSV) и **Печать**.

### Сотрудники

- **Администратор** — всё.
- **Управляющий** — касса, товары, склад, отчёты, отмена продаж; без сотрудников и настроек.
- **Кассир** — касса, просмотр товаров, свои продажи.
- **Свои права** — только отмеченные пункты.

Администратор может сбросить пароль сотруднику и временно отключить доступ. Нельзя отключить себя и лишить прав последнего администратора.

### Настройки

Название киоска, адрес, телефон, символ валюты, минимальный остаток по умолчанию, текст над/под чеком, смена своего пароля, состояние системы (PHP, MySQL, таблицы, права на запись).

### Журнал

Кто, что и когда сделал, с какого IP. Доступен администратору.

## 5. Импорт из Excel / CSV

**Товары → Импорт.** Поддерживаются `.xlsx` и `.csv`.

| Колонка | Обязательна | Пример |
|---|---|---|
| Наименование | да | Бон аква 1 л |
| Закупка | нет | 50 |
| Продажа | да | 90 |
| Остаток | нет | 12 |
| Категория | нет | Напитки |
| Артикул | нет | A-001 |
| Ед. | нет | шт |
| Мин. остаток | нет | 3 |

- Заголовки ищутся в первых 15 строках, порядок колонок не важен.
- Товары сопоставляются по названию: существующие обновляются, новые добавляются.
- Галочка «Обновлять цены» управляет перезаписью цен.
- «Остаток» применяется как фактический остаток.
- Шаблон CSV скачивается в окне импорта.

## 6. Обновление сайта

Код на хостинге получен через `git clone`, поэтому обновление — одна команда:

```bash
ssh mahmadgv@mahmadgv.beget.tech
cd ~/piz.itop7.ru/public_html
git pull --ff-only
```

`config/config.php` и `uploads/` не в Git, поэтому не перезаписываются.

Если менялась схема базы, в описании обновления будет отдельная команда. Текущая версия дополнительных миграций не требует.

## 7. Резервные копии

1. Панель Beget делает ежедневный бэкап аккаунта — уточните глубину хранения в тарифе.
2. Раз в неделю скачивайте:
   - дамп базы через **phpMyAdmin → Экспорт**;
   - папку `uploads/` (фото) по FTP;
   - CSV из «Продаж» и «Товаров».
3. Перед обновлениями — бэкап вручную.

## 8. HTTPS — обязательный шаг

Сейчас сайт работает по HTTP, пароль передаётся открыто.

1. https://cp.beget.com → **Сайты** → `piz.itop7.ru` → **SSL-сертификаты**.
2. Выпустите бесплатный **Let's Encrypt** (нужен e-mail).
3. Дождитесь выпуска (обычно 5–15 минут).
4. Включите перенаправление HTTP → HTTPS, если доступно.
5. Проверьте https://piz.itop7.ru.
6. Выйдите и войдите заново — cookie станут `Secure`.
7. Смените пароль администратора в **Настройках → Безопасность**, если он вводился по HTTP.

## 9. Безопасность

- `info.txt` и `config/config.php` не в Git и закрыты `.htaccess`.
- Пароли — `password_hash` (bcrypt).
- CSRF-токен на всех POST, сессия `HttpOnly` + `SameSite=Lax`.
- 5 неудачных входов — блокировка на 15 минут.
- Фото перекодируются в JPEG; в `uploads/` запрещено исполнение PHP.
- CSP, `X-Frame-Options`, `nosniff`, `X-Robots-Tag: noindex`.
- API без входа — 401; служебные файлы — 403.
- Не публикуйте `info.txt` и не пересылайте пароль базы в мессенджерах.

## 10. Если что-то не работает

| Симптом | Что сделать |
|---|---|
| 500 | `tail -40 ~/piz.itop7.ru/public_html/storage/logs/php-error.log` |
| 404 на всех страницах | проверьте `.htaccess` и `mod_rewrite`; файл должен быть в `public_html` |
| «Нет подключения к базе» | хост `localhost`, база/пользователь `mahmadgv_piz`, пароль из `info.txt` |
| Не грузятся фото | права `775` на `uploads/`, включён GD |
| Excel не импортируется | включите `zip` или сохраните как CSV |
| 403 на всём сайте | корень сайта должен указывать на папку с `index.php` |
| HTTPS не открывается | сертификат не выпущен/не применён в панели |

Проверка сервиса: http://piz.itop7.ru/healthz (после SSL — https).

## 12. Локальный запуск

```bash
php -S 127.0.0.1:8080 tools/dev-server.php
```

Нужны PHP 8.1+ (`pdo_mysql`, `mbstring`, `fileinfo`, желательно `gd`, `zip`) и MySQL.
Откройте http://127.0.0.1:8080/setup.
