# Что внедрять в PIZZA / КИОСК ДОНЕР по опыту HoReCa-систем

Источник: [Adesk — ТОП-12 программ для автоматизации ресторана и кафе в 2026 году](https://adesk.ru/blog/po-dlia-obshchepita-top-12-programm-dlia-avtomatizatsii-restorana-i-kafe-v-2026-godu/).

## Главный вывод статьи

Автоматизация нужна не ради кассы, а чтобы связать:

**продажа → техкарта → расход ингредиентов → остаток → закупка → себестоимость → прибыль.**

Где теряются деньги без этой связи:

- фудкост и списания;
- недостачи, забытые чеки, скидки «для своих»;
- касса, склад и финансы живут в разных таблицах;
- инвентаризация и закупки не сходятся с продажами.

## Что из статьи уже есть у нас

- Касса, оплата, чеки, скидки, смены.
- Товары, остатки, приход партиями, расход/списания.
- Отрицательные остатки, инвентаризация, история цен.
- Роли и права, журнал действий.
- Отчёты по выручке, прибыли, оплате, топу товаров.
- PWA и мобильная касса.

## Чего не хватает для полноценного общепита

| Блок | Сейчас | Нужно |
|---|---|---|
| Техкарты | Нет | Рецептуры блюд: ингредиенты, граммы, потери |
| Списание ингредиентов | Нет | Автоматически при продаже блюда |
| Фудкост | Только средняя себестоимость товара | Себестоимость и фудкост по каждому блюду |
| Модификаторы | Нет | Соус, сыр, размер, без лука, комбо |
| Стоп-лист | Нет | Авто-стоп при нехватке ингредиентов + ручной |
| Инвентаризация | Корректировка остатка | Сессия пересчёта, расхождения, акт |
| Поставщики | Нет | Поставщик, накладная, цена, долг |
| Касса/наличные | Итоги смены | Открытие/закрытие кассы, инкассация, недостача |
| Фискализация | Внутренний чек | 54-ФЗ, ОФД, онлайн-касса |
| Маркировка | Нет | «Честный знак» для маркируемых товаров |
| Кухня | Нет | Очередь заказов / KDS, статусы «готовится/готово» |
| Лояльность | Нет | Клиенты, бонусы, промокоды |
| Доставка | Нет | Самовывоз, агрегаторы, статусы |
| Офлайн-продажи | Только офлайн-заглушка | Очередь продаж при обрыве интернета |
| 1С/бухгалтерия | Нет | Выгрузка/API |

## Что внедрять в первую очередь

### P0 — учёт производства и денег

1. **Ингредиенты и техкарты**
   - Разделить товары на: готовое блюдо, ингредиент, полуфабрикат.
   - Для блюда — состав: ингредиент, количество, единица, потери.
   - При продаже блюда списывать ингредиенты по техкарте.

2. **Фудкост и себестоимость блюда**
   - Себестоимость = сумма ингредиентов по средней/партионной цене.
   - Фудкост % = себестоимость / цена продажи.
   - Отчёт по маржинальности каждого блюда.

3. **Стоп-лист**
   - Автоматически: если ингредиента не хватает.
   - Вручную: закончился соус/заготовка.
   - Касса не даёт продать стоп-позицию.

4. **Инвентаризация как документ**
   - Сессия: кто, когда, склад.
   - Расчётный остаток, фактический, расхождение.
   - Акт недостачи/излишка, списание.

5. **Касса и наличные**
   - Открытие смены с разменной суммой.
   - Внесение/изъятие, инкассация.
   - Фактическая касса vs расчётная, недостача/излишек.

6. **Фискализация 54-ФЗ**
   - Не писать свою онлайн-кассу; интегрироваться с АТОЛ/Эвотор/CloudKassir.
   - Хранить фискальный признак, чек, смену, ОФД.
   - Это обязательный внешний контур, а не «ещё одна кнопка».

### P1 — операционка и контроль

7. **Модификаторы и комбо**
   - Соус, сыр, двойное мясо, без лука, размер.
   - Влияние на техкарту и цену.

8. **Поставщики и накладные**
   - Поставщик, документ, позиции, цена, срок.
   - Долг поставщику, история цен.

9. **Лимиты скидок и причины**
   - Кто может дать скидку, до какого %.
   - Причина отмены/скидки, журнал.

10. **Очередь заказов / мини-KDS**
    - Номер заказа, состав, статус «принят/готовится/готов».
    - Экран выдачи для киоска.
    - Не делать полноценный зал и столы — они киоску не нужны.

11. **Офлайн-продажи**
    - Очередь чеков в браузере при обрыве интернета.
    - Синхронизация с защитой от дублей.
    - Это сложнее, чем офлайн-страница; делать после техкарт.

12. **Аналитика**
    - Фудкост, списания, ABC, продажи по часам, средний чек, стоп-лист, остатки, оборачиваемость.

### P2 — рост

13. **Клиенты и лояльность** — телефон, бонусы, промокоды, повторные заказы.
14. **Самовывоз/доставка/QR-меню** — если киоск начнёт принимать заказы заранее.
15. **Эквайринг** — интеграция с терминалом, а не ручная отметка «карта».
16. **1С/бухгалтерия** — выгрузка продаж, закупок, зарплат.
17. **Учёт времени сотрудников** — табель, ставки, премии.
18. **AI-прогноз** — спрос, автозаказ, оптимизация меню; только после чистых данных.

## Что не копировать у больших систем

Для одного киоска избыточны:

- план зала, столы, бронирование, официанты;
- ЕГАИС (если нет алкоголя);
- франшиза и управление сетью;
- полноценная ERP на 1С;
- собственная онлайн-касса и ОФД;
- курьерская логистика.

Эти функции есть в iiko, r_keeper, Трактиръ, 1С:Общепит, но киоску они не нужны.

## На какие системы ориентироваться

- **Rebase, Quick Resto, Restik, Dooglys** — ближе всего: касса, кухня, склад, техкарты, доставка, лояльность.
- **Frontpad** — если главное заказы и доставка, низкий порог.
- **Saby Presto, Tillypad** — полезны идеи ролей, KDS, стоп-листов, модульности.
- **iiko, r_keeper, 1С** — брать только идеи учёта, не всю сложность.
- **Контур.Маркет** — ориентир по маркировке, ЕГАИС, «Меркурию»; лучше интеграция, чем своя реализация.

## План на 3 этапа

### Этап 1. Производственный учёт — 3–4 недели

- ингредиенты, техкарты, полуфабрикаты;
- автосписание при продаже;
- фудкост и маржинальность;
- стоп-лист;
- инвентаризация с актом;
- отчёты по списаниям и расхождениям.

### Этап 2. Деньги и соответствие — 2–3 недели

- касса/инкассация/недостачи;
- фискализация через готовую онлайн-кассу;
- поставщики и накладные;
- лимиты скидок;
- маркировка, если нужна.

### Этап 3. Рост — 3–5 недель

- модификаторы/комбо;
- очередь заказов и экран выдачи;
- офлайн-продажи;
- лояльность;
- доставка/QR;
- 1С/API.

## Рекомендация

Следующий релиз делать не «ещё одну кассу», а **v1.25.26: техкарты + ингредиенты + автосписание + фудкост + стоп-лист**. Это даст самый большой управленческий эффект и закроет главный разрыв с HoReCa-системами.

Фискализацию и маркировку не писать самостоятельно — интегрировать готовые сервисы. Зал, брони, ЕГАИС и ERP не внедрять: формат киоска их не требует.
